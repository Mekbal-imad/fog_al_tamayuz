# منصة فوج التميز

مشروع أولي قابل للتطوير لإدارة فوج حفظ القرآن الكريم.

## المتطلبات
- Node.js 20 أو أحدث
- حساب Supabase
- حساب Vercel للنشر (اختياري أثناء التطوير)

## 1) تثبيت المشروع
```bash
npm install
```

## 2) إعداد Supabase
1. أنشئ مشروعًا جديدًا في https://supabase.com/dashboard
2. افتح SQL Editor.
3. انسخ محتوى `database/schema.sql` ونفّذه.
4. من Project Settings > API انسخ Project URL و anon/public key.

## 3) إعداد متغيرات البيئة
انسخ `.env.example` إلى `.env.local`، ثم أدخل القيم:
```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

## 4) إنشاء حساب المشرف
1. من Supabase افتح Authentication > Users.
2. أنشئ مستخدمًا ببريد إلكتروني وكلمة مرور قوية.
3. انسخ UUID الخاص بالمستخدم.
4. في SQL Editor نفّذ، بعد استبدال القيم:
```sql
insert into public.profiles (id, full_name, role)
values ('UUID_FROM_AUTH_USERS', 'اسم المشرف', 'supervisor');
```
5. لا تفعّل التسجيل العام للمستخدمين.

## 5) تشغيل محلي
```bash
npm run dev
```
ثم افتح http://localhost:3000

## ما تتضمنه هذه النسخة
- واجهة عربية RTL وهوية خضراء/بيج/ذهبية.
- تسجيل دخول عبر Supabase Auth.
- لوحة تحكم تقرأ بيانات التلاميذ والحضور والتقييمات من قاعدة البيانات.
- قاعدة بيانات تشمل التلاميذ، الحصص، الحضور، الحفظ والمراجعة، الاختبارات الشهرية، والإعدادات.
- قيود تحقق على علامات التقييم والاختبار الشهري.

## ملاحظات مهمة قبل الاستخدام الفعلي
- هذه هي المرحلة الأولى (الأساس التقني ولوحة التحكم). أقسام إدارة السجلات التفصيلية لا تزال بحاجة إلى بناء واجهات CRUD واختبارها.
- أُنشئت سياسات RLS لتقييد الوصول إلى فريق الإدارة/الإشراف. بوابة الأولياء لم تُفعّل بعد؛ يجب بناء سياسات مستقلة تربط كل ولي بأبنائه قبل إتاحتها.
- لا تضع `service_role` key في الواجهة أو في متغير يبدأ بـ `NEXT_PUBLIC_`.
- قبل إدخال بيانات حقيقية لقاصرين، اختبر الصلاحيات بحسابات تجريبية وتأكد من عدم تسرب بيانات طالب إلى ولي أمر آخر.
- خذ نسخة احتياطية دورية من قاعدة البيانات.

## المرحلة الثانية: إدارة الطلبة والملفات الشخصية

تتضمن هذه المرحلة:
- صفحة `/students` لعرض الطلبة والبحث والتصفية حسب الحالة.
- صفحة `/students/new` لإضافة طالب.
- صفحة `/students/[id]` لعرض الملف الشخصي.
- صفحة `/students/[id]/edit` لتعديل بيانات الطالب.
- تعطيل/إعادة تفعيل الطالب دون حذف سجلاته.
- Migration قاعدة البيانات في `database/migrations/20261123_student_management.sql`.

### تطبيق تحديث قاعدة البيانات
1. خذ نسخة احتياطية من قاعدة بيانات Supabase.
2. افتح Supabase Dashboard ثم SQL Editor.
3. نفّذ محتوى `database/migrations/20261123_student_management.sql` مرة واحدة.
4. لا تعِد تنفيذ `database/schema.sql` على قاعدة البيانات الحالية؛ فهو ملف تأسيس المرحلة الأولى وليس Migration لهذه المرحلة.

### دمج ونشر ملفات المرحلة الثانية
- أضف مجلد `components` و`lib` والصفحات الجديدة داخل `app/students`.
- استبدل `app/page.tsx` و`app/globals.css` بالنسختين الموجودتين في هذه الحزمة، أو ادمج التغييرات إذا كانت هناك تعديلات محلية لاحقة.
- حافظ على `.env.local` الحالي ولا ترفعه إلى GitHub.
- نفّذ `npm install` ثم `npm run build` للتحقق، وبعد نجاح البناء انشر المشروع بالطريقة المعتادة.

### الصلاحيات
تستخدم الصفحات Supabase browser client بمفتاح anon/public فقط، وتعتمد على جلسة المستخدم وسياسات RLS الموجودة. لا تضف `service_role` إلى الواجهة الأمامية ولا تفتح سياسات عامة لجدول الطلبة. يجب أن يكون للمستخدم المسجل صف في `public.profiles` بدور `supervisor` أو `admin` حتى تسمح له سياسة `is_staff()` الحالية بإدارة بيانات الطلبة.

### حدود هذه المرحلة
أقسام الحضور والحفظ والمراجعة والاختبارات والتقارير الظاهرة في ملف الطالب مجرد عناصر تمهيدية، ولا تنفذ عمليات تسجيل أو تقييم في هذه المرحلة.
